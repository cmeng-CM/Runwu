## 1. 总体结论

**可实施。**

v1.5 对 004 的修复总体有效，未发现新的阻塞项：

- **N-14/N-20 闭合**：`applyTranslationSettings` 先按上次配置计算 `sourceChanged/modelsChanged/timeoutChanged/targetChanged/backendChanged`，`affectsCalibration = source||models||timeout`；`invalidateRealtime` 传 `alsoClearCalibration: affectsCalibration`；仅 `sourceChanged` 调 `input.setSourceLanguage`，且 `setSourceLanguage` 同语言直接返回、不 `reset`；仅 `affectsCalibration` 追加校准重配。目标语言/后端变化不再经 `invalidateRealtime`/`onEmpty` 取消校准在途，A16 覆盖两组。
- **N-17 闭合**：`onRouteChanged` 改为在 `handle`/`observe` 每次快照抽句后立即计算，不经防抖；`emit` 仍按防抖发请求；A5 增加 0–450ms 窗口用例。路由变化的状态失效不再被 450ms 延迟。
- **N-19 闭合**：`fittingSizeNatural` 明确来自未设置 `textHeightLimit`、未安装滚动约束的临时 `NSHostingView`（同宽度、真实文案），不得使用滚动宿主 fitting；`effectiveNatural = max(measuredNatural, fittingSizeNatural)`。测量低估能被发现，非滚动卡不再因滚动宿主塌缩而裁切。
- **N-21 闭合**：`effectiveNatural > cardHeightLimit` 时显式 `forceScroll`，`textHeightLimit = max(cardHeightLimit - chrome, 60)`，面板 = `cardHeightLimit`，正文滚动；不再依赖 `OverlaySizing.plan` 的极端 chrome 保护。A8 增加超限用例。
- **N-18 闭合**：4.1 第 4 条改述为“不失效校准状态、不取消新校准请求；`hideRealtime` 顺带收起未钉住旧校准卡是期望行为”，与 `clearRealtimePresentation(alsoClearCalibration:false)` 的实际行为一致。

仅保留 2 项**非阻塞**问题：

1. **N-22**：`applyTranslationSettings` 在目标语言/后端变化时仍执行 `overlay.hideUnpinned(except:)`（App.swift:362）和 `invalidateRealtime(false)` → `clearRealtimePresentation(false)` → `overlay.hideRealtime`（App.swift:629）。这些会收起“已显示”的未钉住校准卡；4.4 只承诺“不失效校准状态”，A16 写“不失效校准卡”，两者对“卡”还是“状态”不完全一致。A16 的场景是“校准请求在途”（尚无卡），因此不影响 N-14 的在途目标；若用户已有校准卡显示，目标语言/后端变化会让卡消失，后续无请求可恢复。非阻塞，但建议对齐文案或抑制该路径的校准卡收起。
2. **N-23**：`forceScroll` 的 `textHeightLimit = max(cardHeightLimit - chrome, 60)` 在 `chrome + 60 > cardHeightLimit` 时，面板 = `cardHeightLimit`，但 `chrome + 60` 已超过面板，正文仍会裁切；正常 chrome（约 50–70pt，limit 240–460）不会触发，属于极端字号/布局边界。非阻塞，但“超限不裁切”的承诺在该边界不成立。

因此 v1.5 可以进入计划与实施；N-22/N-23 可在实施计划中顺带处理，不影响总体可实施性。

## 3. 新发现问题

### 3.1 非阻塞问题

#### N-22 目标语言/后端变化仍会收起“已显示”的未钉住校准卡，A16 的“不失效校准卡”需限定为状态

- **位置**：v1.5 4.4 252 行（“目标语言/翻译后端变化时为 false，不取消校准在途、不失效校准状态”）、A16 397 行（“前者不取消校准在途、不失效校准卡”）；代码 `Sources/Pico/App.swift:346-377`（357 行 `invalidateRealtime`、362 行 `overlay.hideUnpinned`）、`App.swift:626-637`（629 行 `overlay.hideRealtime`）。
- **依据**：
  - `applyTranslationSettings` 在目标语言/后端变化时传 `alsoClearCalibration:false`，因此不会 `invalidateCalibrationState`/取消校准请求，N-14 的在途目标达成。
  - 但该函数仍无条件执行 `invalidateRealtime(clearAnchor:true, preservingEntry:)`。`invalidateRealtime` → `clearRealtimePresentation` → `overlay.hideRealtime` 会移除所有未钉住的 `.realtime` 卡，包括已显示的校准卡。
  - 随后 `overlay.hideUnpinned(except:)`（App.swift:362）又会移除所有未钉住卡（包括校准卡）。
  - 结果是：如果校准卡已经显示（请求已完成，不在途），改目标语言/翻译后端会让卡消失；由于没有在途请求，之后不会自动恢复。状态仍是 `.calibrate`，但卡已收起。
  - 4.4 只承诺“不失效校准状态”，A16 写“不失效校准卡”；如果 A16 只测“请求在途”（尚无卡），测试会通过；如果测“卡已显示”，会失败。
- **影响**：用户改目标语言/翻译后端时，已显示的校准卡被收起；不是 N-14 的“在途取消”，但与 A16 的“不失效校准卡”措辞冲突，属于新的设置/清理不一致。
- **是否阻塞**：否（N-14 的在途目标已达成；A16 场景为在途）。建议在实施前对齐。
- **修复方向**：二选一：
  1. 把 A16 的“不失效校准卡”改为“不失效校准状态；已显示的未钉住卡可能被设置变更收起”，并在 4.4 说明该行为；或
  2. 在目标语言/后端变化时，让 `applyTranslationSettings` 使用 translation-only 的收起（不调用 `overlay.hideRealtime`/`hideUnpinned` 的校准卡部分），保留已显示校准卡；这需要 `OverlayCoordinator` 提供按内容类型隐藏的入口，或在 `clearRealtimePresentation(alsoClearCalibration:false)` 中只隐藏 `.translation` 内容。

#### N-23 `forceScroll` 的 `max(cardHeightLimit - chrome, 60)` 在极端 chrome 下仍可能裁切

- **位置**：v1.5 4.3 239 行；A8 389 行；代码 `Overlay.swift:1108-1111`（`cardHeightLimit`）、`Overlay.swift:1091-1101`（`installContent` 的 chrome/plan）。
- **依据**：`textHeightLimit = max(cardHeightLimit - chrome, 60)`，面板 = `cardHeightLimit`。当 `chrome + 60 > cardHeightLimit`（例如可访问性大字号/极端布局把 shell chrome 推到 180pt 以上，而 `cardHeightLimit` 只有 240）时，正文至少 60pt，加上 chrome 超过面板，仍会裁切；`forceScroll` 无法在面板高度内同时容纳 chrome 和最小 60pt 正文。
- **影响**：极端字号/布局下“超限不裁切”的承诺不成立；正常 chrome 约 50–70pt，不触发。
- **是否阻塞**：否（正常场景无影响；属于边界）。
- **修复方向**：在 `chrome + 60 > cardHeightLimit` 时，二选一：
  1. 允许面板高度 = `max(cardHeightLimit, chrome + 60)`（牺牲上限，保证不裁切）；或
  2. 把 `textHeightLimit` 下限改为 `max(cardHeightLimit - chrome, 0)`，允许正文小于 60pt，并在卡片视图的 `minBodyHeight`/resize 逻辑中相应放宽；或
  3. 在设置/实现中限制 chrome 上限，使 `chrome + 60 <= cardHeightLimit`。
  A8 增加一条“大字号/大 chrome”边界用例，明确预期是面板增长还是正文缩小。
