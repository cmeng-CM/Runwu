## 2. 发现清单

### 缺陷（阻塞）

**R2-01 校准卡从未获得光标锚点，默认设置下出卡时不可见（4.3/A2）**
- 位置：`Sources/Pico/App.swift:225-228`（`monitor.onAnchorChanged` 只喂 `realtime.updateAnchor`，全仓无 `calibration.updateAnchor` 调用点）；后果链 `Sources/Pico/App.swift:812`（`acceptCalibrationResult` 以 `anchor: calibration.anchor` 出卡，恒为 nil）→ `Sources/Pico/Overlay.swift:1852`（`showCalibration` 传 nil）→ `Overlay.swift:1900-1913`（realtime + `followCaret`（默认 true，Settings.swift:493）且 `inputAnchor == nil` 时 `panel.orderOut(nil)`）；`Overlay.swift:1364` 亦不对 realtime+followCaret 卡 orderFront。
- 影响：`CalibrationState.anchor` 永远为 nil，出卡时 entry 无 `inputAnchor`/`avoid`，screen 回退 `NSScreen.main`。用户停顿（A2 核心场景）后光标静止——`onAnchorChanged` 仅在光标几何变化时触发（Input.swift:524-534）——校准卡被 orderOut，**直到用户再次移动光标/继续输入才出现**；且无输入框避让、多屏时落错屏。设计 4.3「origin 与布局：复用 .realtime(session)，跟随光标、输入框避让……全部继承」未实现；README「校准卡跟随光标」承诺与实现不符。
- 为何测试未拦：`CalibrationStateTests` 单测了 `updateAnchor`（有断言、非恒真），但生产代码从未接线；`CalibrationIntegrationTests.sendLive` 直接调 `monitor.onAnchorChanged` 也只喂到 realtime 侧，而断言用 `cardContents`（统计全部 entries，Overlay.swift:1159-1165，不筛 `panel.isVisible`），面板被 orderOut 仍计数为 1，故全绿。
- 建议修复：`monitor.onAnchorChanged` 中追加 `calibration.updateAnchor(anchor, session: session)`（一行接线；overlay 侧已有 `hideRealtimeCalibration`/`updateAnchor` 对 realtime origin 的通配，无需其他改动），并补一条「出卡后 `shownEntryIDs` 非空」的集成断言（见 R2-10）。

## 4. 实现质量核对（摘要）

- **并发/取消**：`CalibrationCoordinator` actor 内 generation+Task 取消代次语义正确（新请求取代旧请求、迟到结果/过期 revision 一律转 CancellationError 不计失败）；`CalibrationState` 令牌语义镜像翻译态；`calibrate` Task 出卡前五重校验；设置变更经 `calibrationConfigurationTask` barrier 串行化 reconfigure。未发现竞态窗口。

### 7.2 残留问题（非阻塞，不改变结论）

- **R2-11（建议，新发现）**：失焦路径 `invalidateCalibrationState()` 调 `calibration.invalidate()` 未传 `clearAnchor: true`（realtime 侧在同路径清了 anchor+session）。后果：换焦点后新 session 的**首个**锚点事件会被 `updateAnchor` 的 session 比对拒绝（旧 session 残留），锚点要等新 session 首个快照切换 session 后的下次光标移动才可用——存在"焦点切换后仅一次几何变化即停顿"的窄窗口内首张校准卡暂无锚点（下次光标移动即恢复）。常规连续输入（每击键都动光标）不触发。建议后续：失焦路径对 calibration 传 `clearAnchor: true`，或 `updateAnchor` 在 `sentence == nil` 时放宽 session 采纳。
- **R2-12（记录，口径出入）**：修复说明称"startup/routeSwaps/consecutive/failure/isolation 出卡等待全部改为 shownEntryIDs"，实际仅 routeSwaps/consecutive/failure 收紧；startup（CalibrationIntegrationTests.swift:83）与 isolation（:206）两处仍等 `cardContents`。关键回归网已由收紧的三处覆盖，不影响结论，仅记录口径准确性。
